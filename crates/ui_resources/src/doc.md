# ui_resources

Resources the UI consumes but no UI logic: the embedded icon assets GPUI loads by path, and
the localization string tables. GPUI-light (only `SharedString` and `AssetSource`), so any
crate can read a string without depending on the app.

Not here: the app icon pipeline (`assets/app-icon/` is generated by `scripts/gen-icons.sh`
from `assets/sloptaster.svg` and read by `cargo packager`, Flatpak and the Windows resource,
not embedded); which language is active at startup (`sloptaster/src/main.rs`).

## Files

- `assets.rs` — `Assets`, the `AssetSource` over `assets/icons/**` embedded with `rust-embed`.
- `i18n/mod.rs` — the `Strings` schema, `lang!` / `languages!`, `Lang`, the active-language
  atomic (`set_active`, `active`, `strings`), interpolation accessors.
- `i18n/en.rs`, `i18n/ru.rs` — one `static` table per language.
- `../build.rs` — reruns the build when any file under `assets/` changes, so `rust-embed`
  picks up new icons.

## Rules

- Icons are looked up by gpui-component as `icons/<name>.svg` (its `IconName` paths); a
  missing file is an error at render time, not at build time. Keep the ones gpui-component's
  notifications and Linux title bar use (`info`, `circle-check`, `circle-x`,
  `triangle-alert`, `close`, `window-*`).
- A new string is a field on `Strings` plus a line in every language file; `lang!` builds a
  full struct literal, so a language missing a key does not compile.
- Interpolated strings keep a `{}` template in a `*_t` field and are read only through an
  accessor on `impl Strings`; a test checks every template has exactly one placeholder.
- `Lang::from_locale` matches the language prefix of an OS locale and falls back to English.
