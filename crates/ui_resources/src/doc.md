# ui_resources

Resources the UI consumes but no UI logic: the embedded icon assets GPUI loads by path, the
bundled theme JSON and the user themes folder (with Zed theme import), and the localization
string tables. GPUI-light (only `SharedString` and `AssetSource`), so any
crate can read a string without depending on the app.

Not here: the app icon pipeline (`assets/app-icon/` is generated by `scripts/gen-icons.sh`
from `assets/slopcop.svg` and read by `cargo packager`, Flatpak and the Windows resource,
not embedded); which language is active at startup (`slopcop/src/main.rs`); the Zed → gpui-component
conversion itself (`zed_theme`); applying a theme or syntax palette (`slopcop/src/settings_store.rs`).

## Files

- `assets.rs` — `Assets`, the `AssetSource`: own SVGs in `assets/icons/**` first, then the
  Lucide icons picked from `gpui-kit-assets` with `icon_assets!` (`ExtraIcons`), then
  `gpui-kit-assets`' default component icons. `Icons` re-exports the shared `IconName`.
- `themes.rs` — `themes_dir`; `register_bundled_themes`: writes `themes/*.json` to the data
  dir's `themes/` and registers that folder with `ThemeRegistry`; `zed_theme_files` (theme
  JSON in Zed's installed extensions and its user themes folder); `import_zed_theme`
  (convert with `zed_theme`, write `zed-<family>.json` into the themes folder).
- `themes_tests.rs` — an imported Zed family loads as gpui-component's `ThemeSet`;
  re-import keeps its names; a non-theme file writes nothing.
- `themes/` — one JSON per theme family.
- `i18n/mod.rs` — the `Strings` schema, `lang!` / `languages!`, `Lang`, the active-language
  atomic (`set_active`, `active`, `strings`), interpolation accessors.
- `i18n/en.rs`, `i18n/ru.rs` — one `static` table per language.
- `../build.rs` — reruns the build when any file under `assets/` changes, so `rust-embed`
  picks up new icons.

## Rules

- The themes folder holds the bundled files (rewritten at every start) and the user's own;
  the registry watches it, so a file written there appears without a restart. Imports are
  named `zed-*.json` and so never collide with a bundled file. Writes go through a
  `.json.tmp` file the registry ignores, then a rename.
- Zed's folders: extensions in its data dir (`~/Library/Application Support/Zed`,
  `$XDG_DATA_HOME/zed`, `%LOCALAPPDATA%\Zed`) under `extensions/installed/*/themes/`, user
  themes in `~/.config/zed/themes` (macOS), `$XDG_CONFIG_HOME/zed/themes` (Linux),
  `%APPDATA%\Zed\themes` (Windows). Both are blocking reads: call them off the UI thread.
- On import, a name the registry already has counts as taken (the registry keeps the first
  of a name), except names the replaced `zed-*.json` itself defined, so re-importing a
  family keeps its names.
- Icons are looked up by gpui-component as `icons/<name>.svg` (its `IconName` paths); a
  missing file is an error at render time, not at build time. An `Icons::X` used by the app
  must be listed in `ExtraIcons` unless it is one of `gpui-kit-assets`' defaults. Keep the ones gpui-component's
  notifications and Linux title bar use (`info`, `circle-check`, `circle-x`,
  `triangle-alert`, `close`, `window-*`).
- A new string is a field on `Strings` plus a line in every language file; `lang!` builds a
  full struct literal, so a language missing a key does not compile.
- Interpolated strings keep a `{}` template in a `*_t` field and are read only through an
  accessor on `impl Strings`; a test checks each template's placeholder count, since `fill`
  silently drops mismatched arguments.
- `Lang::from_locale` matches the language prefix of an OS locale and falls back to English.
